# Manifold 1.1.0

Manifold is a self-hosted web application that reads live data from your plant's brokers, OPC UA servers and devices, shows it as one browsable namespace, and republishes it in a clean, consistent shape for other systems. This is the first public release.

## Highlights

**Devices and drivers**
- Read-only drivers for Siemens S7, EtherNet/IP (Logix), BACnet/IP, SNMP, HTTP/JSON, MTConnect, CoAP, and Matter and Z-Wave through their bridge servers, next to Modbus TCP. Every frame goes through an allowlisted read-only encoder.
- Devices table with a detail drawer, device profiles, all-or-nothing bulk creation, probe, import from controller or device, and polling health with the device's reason for every quarantined tag.

**IoT**
- Zigbee2MQTT, Z-Wave JS UI, Home Assistant discovery, Tasmota, Shelly, ChirpStack and The Things Stack traffic on a broker becomes devices with named tags. Manifold only subscribes; it never publishes to them.

**Mapping and UNS**
- A single-sheet mapping editor: tags by list or by rule, per-tag units, scale, states, limits and context, `_status` and `_meta` topics, quality, Sparkplug B output, MQTT topics and IoT devices as sources, and a direct historian target. The server previews exactly what it would publish.

**Alerts**
- An Alerts page with severities, active alarms, acknowledgement with notes, and a history that survives restarts (CSV export).

**Brokers**
- A read-only security posture per broker, an opt-in round-trip canary and public test-broker presets.

**Codecs and exports**
- CBOR, MessagePack, SenML, Protobuf and Avro payload decoding; Trends CSV export.

**Security**
- Token-less local instances refuse foreign host names and origins; secrets no longer follow an address change; webhook URLs are secrets; link-local and cloud-metadata targets are refused; auth fails closed.

**UI**
- A redesigned interface with light, dark and system themes; every page is checked automatically for accessibility in both themes.

## Upgrade notes

- A token-less instance on loopback answers only to `localhost`, `127.x` and `::1` (421 otherwise); add names with `MANIFOLD_ALLOWED_HOSTS`.
- Changing a connection's scheme, host or port requires its password, token or community again (400 `secret-required`).
- Alert rules moved from Settings to the Alerts page.
- Webhook URLs are no longer returned; clearing one needs `webhookUrl: ""`.
- Stored device secrets are answered as `null`.
- `GET /api/recorder/:id/series` requires `tags`; canary topics must be under `manifold/canary/`.
- With no token the server binds `127.0.0.1` only; in a container, pass a token. `/metrics` needs a token when auth is on.
- Device live values arrive as one batched `device-values` Socket.IO event every 250 ms.

The full list is in the changelog's Upgrade notes.

## Verification status

CI proves MQTT intake and MQTT 5 against a real EMQX broker, writes and Trends read-back against real InfluxDB, TimescaleDB and Timebase (1.3.4) containers, and OPC UA (including Sign and SignAndEncrypt) against a real node-opcua server. No device driver and no IoT convention has been run against real hardware: every driver beyond Modbus TCP is experimental and was tested only against simulators written with it, and the IoT conventions only against a simulator of their documented messages. Some Timebase REST behaviour is unconfirmed, and the public test-broker presets were written from memory. If you have a PLC, the checklist is in the wiki: Verifying on real hardware.

## Run it

```bash
docker run -p 5000:5000 -v manifold-data:/data \
  -e MANIFOLD_AUTH_TOKEN=$(openssl rand -hex 24) \
  ghcr.io/zbest1000/manifold:1.1.0
# open http://localhost:5000 and enter the token
```

From source (Node.js 20.19+ or 22.12+):

```bash
npm run install:all
npm run build && npm start    # http://localhost:5000
```
