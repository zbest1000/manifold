# Review, November 2026: server, UI, and readiness for device drivers

A point-in-time review. Findings marked **[confirmed]** were re-read in the
code by a second pass; the rest were reported by a single reviewer with
file references and should be confirmed when picked up. Line numbers are as
of commit `f5df716f`.

How it was run: the server test suite passed (160 tests: 155 pass, 0 fail,
5 skipped). The client was built and exercised live against a local broker
fed by `docker/simulator/sim.js` (about 325 topics, three Sparkplug edge
nodes), with all 14 pages visited at 1440×900 and 390×844; there were no
console errors. OPC UA, CESMII and i3X pages were seen in their empty states
only, and the Pipelines creation wizard was not walked.

## What is done well

- The MQTT hot path: coalesced, bounded by topics touched, struct-of-arrays
  store, volatile socket batches, per-row tap error isolation.
- The compiled-view pattern keeps per-message engine cost to an integer
  compare, and makes live config edits cheap.
- Auth: timing-safe compare, one path for REST and socket, failure
  throttling, loopback-only without a token.
- Historian writes: parameterised SQL, identifier allow-list, explicit and
  reported outbox bounds with a drop policy.
- Sparkplug publisher implements real BIRTH/DEATH/will semantics.
- The UI has a coherent navigation grouping, good empty state on Pipelines,
  and no runtime console errors.

## Server findings

### High

1. **OPC UA bindings go silent after a restart, an edit or a delete**
   [confirmed]. `TagBindings.start()` calls `syncMonitors()` once
   (`server/services/tagBindings.js:84`), before the restored connection has
   a session; the failed key is dropped (`:116`) and nothing retries. The
   only other caller is `POST /bindings`. `monitored` is never cleared when a
   connection is rebuilt. *Fix:* re-sync on the manager's connected event and
   reconcile on binding delete.
2. **A dropped OPC UA connection is never retried** [confirmed].
   `connectionStrategy.maxRetry: 2` (`server/services/opcuaManager.js:181`),
   after which the connection is marked disconnected for good; a failed
   restore at startup is logged once. *Fix:* supervised reconnect with
   backoff and no retry cap.
3. **Sparkplug updates can be lost to coalescing** [confirmed by reading the
   store; not reproduced with a test]. `TopicStore.ingest` keeps only the
   latest payload per topic per 100 ms flush
   (`server/services/topicStore.js:108`). NDATA/DDATA carry only changed
   metrics, so two messages on one topic inside a window lose the first
   message's metrics for the registry, Sparkplug-source bindings, pipelines
   and historian targets. *Fix:* merge metrics per topic in the store, or tap
   Sparkplug un-coalesced. Worth a reproducing test first.
4. **Bindings suppress quality-only changes** [confirmed]. `_publishTag`
   compares values only (`tagBindings.js:156-166`), so Good→Bad with an
   unchanged value is never published; data type is dropped and every
   Sparkplug number is encoded as Double; arrays and objects never compare
   equal, so on-change is ineffective for them.
5. **InfluxDB line protocol** [confirmed]. `escTag`
   (`server/services/historians.js:131`) does not escape newlines, so a
   topic containing one injects lines into the write body; `Number(p.value)`
   turns `""` and `null` into `value=0`. A permanently rejected batch blocks
   the spill file head-of-line (`historianOutbox.js:232`). *Fix:* reject
   control characters, require real numbers, dead-letter 4xx batches.

### Medium

6. **Outbox does synchronous disk I/O on the event loop**: the whole spill
   file is read per batch and the remainder rewritten non-atomically
   (`historianOutbox.js:138,175`), so a drain is quadratic and a crash
   mid-write loses the spill.
7. **Egress guard coverage**: historian URLs, alert webhooks
   (`alertEngine.js:334`) and OPC UA/MQTT hosts do not pass through the
   guard; `guardedFetch` follows redirects; `classifyV6`
   (`egressGuard.js:87`) handles only the dotted IPv4-mapped form.
8. **Config export and roles**: webhook URLs are exported in clear
   (`routes/system.js:71`) and readable by viewers; the viewer role is
   blocked from read-only POSTs such as Trends queries (`index.js:157`);
   an unrecognised role in `MANIFOLD_TOKENS` is treated as admin
   (`index.js:97`) — it should fail closed.
9. **Edit-in-place leaves stale state**: the Sparkplug publisher session
   ignores TLS settings, `wsPath` and `mqttVersion` and caches sessions
   forever (`sparkplugPublisher.js:66`); the pg pool cache key excludes the
   password and SSL options (`historians.js:225`); `updateBroker` tears down
   before validating (`mqttManager.js:524`).
10. **Unbounded growth**: topic slots are never freed, so after 2M unique
    topics new topics are dropped everywhere; `msgProps` is unbounded
    (`mqttManager.js:265`); `branch-silent` rules walk the whole trie every
    15 s (`alertEngine.js:187`).
11. **Unthrottled socket emits**: one `opcua-value` emit per value change
    (`opcuaManager.js:490`) and one `publish-success` per published message
    (`mqttManager.js:514`), bypassing the batching used for MQTT ingest.
    `monitor()` can create duplicate subscriptions under concurrent calls.
12. **`profiles.json` durability**: synchronous full-file rewrite on every
    upsert with no fsync; a single `.bak` that is overwritten; unvalidated
    import (`profileStore.js:226-234`, `routes/system.js:88`).

### Low

13. Subscribe failures other than SUBACK refusal are not retried; a transient
    error leaves broker status at `error` until reconnect.
14. Failed REST auth and viewer 403s are not audited (middleware order,
    `index.js:152-195`); `cert` is not redacted; `audit.jsonl` has no
    rotation; `/metrics` is unauthenticated and exposes names.
15. MQTT-sourced envelope and historian timestamps are arrival time, and
    quality is always Good unless Sparkplug decoding fails.

### Test gaps

OPC UA reconnect, startup monitor sync, edit-in-place followed by bindings,
outbox crash and poison batches, Sparkplug same-topic bursts, quality-only
changes. Bindings are tested only against a mocked OPC UA emitter.

## UI findings

Items already tracked in `docs/UI_BACKLOG.md` are omitted.

### High

1. **No mobile layout.** The sidebar is a fixed `w-60` with no breakpoint
   (`client/src/components/Layout.jsx`), so at 390 px the page content gets
   about 150 px: the Tags subtitle wraps one word per line and the tree is
   cut off. *Fix:* off-canvas drawer below `md`, header actions wrap.
2. **No visible keyboard focus.** There is no `:focus-visible` rule in
   `client/src/index.css`; tabbing through the navigation shows nothing.
   *Fix:* one global rule.
3. **The Tags tree is mouse-only.** `TreeNode` is a clickable `div` with no
   role, `tabIndex` or key handling, and the checkbox is `readOnly` with
   `pointer-events-none` (`client/src/pages/Tags.jsx:355-388`). This is the
   entry point for device mapping. *Fix:* `role="tree"`/`treeitem` with
   arrow keys and Space.
4. **Tags does not scale**: no search or filter, no select-all-in-folder, no
   indication of which tags are already bound.
5. **Modals**: no focus trap, `aria-modal` or focus restore in
   `ui.jsx` `Modal`, and several hand-rolled overlays remain (Tags
   `BindWizard` and `CsvImport`, System) beyond those the backlog lists.

### Medium

6. **The binding wizard is under-guided**: no preview of the resolved topic,
   no list of template variables, the format select truncates its own label,
   and **retain is ticked by default** — retained values outlive a dead
   device, which is one of the documented UNS failure modes.
7. **UNS canvas is light grey inside a dark app**, with 10 px low-contrast
   sublabels. The `spBv1.0` branch is labelled "Business Unit", and the
   badge read `live · 0/s` while traffic was flowing.
8. **Inconsistent counts**: Overview showed 8 "Topics Tracked" while Topics
   and UNS showed about 325 (`client/src/pages/Overview.jsx:58`).
9. **Contrast**: about 250 uses of `text-slate-500`/`600` for helper text on
   a near-black background, often at 10 px.
10. **Silent failures**: about 27 `.catch(() => {})`; a failed source list
    leaves a blank tree with no message or retry.
11. **Tags page layout**: unlabelled source select; the Sparkplug
    primary-host control sits beside bindings and belongs on the broker.

### Low

12. Empty states on Tags, Brokers and OPC UA do not lead to the next step.
13. Lists are built from `div`s with no table semantics or sorting.
14. The Topics graph opens with overlapping labels at a few hundred nodes.
15. The lazy-route fallback is plain "Loading…" text.

### Client code health

- Bundle: the main chunk is 1,075 kB (312 kB gzip) because Overview, Topics
  and UNS are not lazy; both `lucide` and `lucide-react` are installed.
- Very large components: `TopicGraph.jsx` 1156 lines, `Pipelines.jsx` 1123,
  `Uns.jsx` 894, `OpcUa.jsx` 640, `Tags.jsx` 627.
- One Zustand store with per-field subscriptions and a `dataTick` that
  re-renders subscribers on every batch; pages poll with `setInterval`.
- No client lint, types, component tests or end-to-end tests. Adding ESLint
  with `react-hooks` and `jsx-a11y`, plus a Playwright smoke test over the
  routes with axe checks, would catch most of the findings above
  automatically.

## Readiness for device drivers

OPC UA is hard-wired into bindings in four places and there is no common tag
source abstraction, quality model beyond OPC UA, or reconnect supervision.
Server findings 1, 2 and 4 are prerequisites for any driver work. The
proposed architecture is in
[`docs/design/southbound-drivers.md`](design/southbound-drivers.md).

## Suggested order

1. Server 1, 2, 4 (binding lifecycle, reconnect, quality) — small, and they
   fix behaviour that is wrong today.
2. Server 3 with a reproducing test; server 5.
3. UI 1–3 (mobile, focus, tree keyboard access) and the retain default.
4. Server 7 and 8 (egress coverage, role parsing fail-closed).
5. Driver phase 0 from the design document.
